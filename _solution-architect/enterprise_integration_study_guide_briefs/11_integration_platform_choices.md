# Handoff brief 11 — Integration platform choices

Create a **standalone study guide** titled *Choosing Enterprise Integration Platforms and Components*. The audience is a senior/principal Enterprise or Integration Solution Architect preparing for vendor-neutral interviews. Aim for roughly 2,500–3,500 words. Label assumptions and verify vendor or product-specific statements using current primary sources.

**Focus:** Distinguish API gateway, ESB, iPaaS/integration platform, event broker, and orchestration engine by responsibility. Explain mediation, transformation, connectors, policy enforcement, asynchronous distribution, and process state. Evaluate overlap; existing platform investment; workload fit; reliability; delivery speed; team skills; operating burden; licensing; lock-in; portability; build versus buy; and platform rationalization.

**Include:**

1. A component responsibility matrix and reference architecture showing where each piece belongs, with a simpler architecture that uses fewer components when requirements allow.
2. A worked selection where a team requests a new platform although the company operates one already. Show evidence gathering, criteria, proof of concept, alternatives, and decision record.
3. A total-cost and operational comparison framework that avoids invented prices but identifies cost drivers.
4. An analysis of how a centralized integration platform can become a bottleneck and options for workload isolation, scaling, quotas, and ownership.
5. Interview questions with strong answers, red flags, and an exercise with answer key.

Keep deep broker mechanics in the messaging guide and security protocol internals in the security guide. Avoid presenting any platform category as automatically required.
